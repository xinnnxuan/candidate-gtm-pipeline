# 04 · Marketing Operations

**What this stage is for:** keeping a strong application from failing at the last mile — on a mis-parsed field, a stale record, or an eligibility answer that answered a different question than the form asked. The release moment is where small errors become official records.

| | |
|---|---|
| **Inputs** | The approved materials · the live form state (fields, parse output, or the actual page) · one canonical facts source |
| **The decision** | *Is this application accurate, complete, and ready to submit?* |
| **Handoff** | A verified application record; after the human Submit click, lifecycle state passes to [05 · Lifecycle Operations](../05-lifecycle-operations/README.md) |
| **Human authority** | The Submit click is human, always — browser-assisted form work stops before it by contract |

## Skills at this stage

| Skill | Role | The judgment it owns |
|---|---|---|
| **[Application Release QA](application-release-qa/SKILL.md)** | lead | Release QA against one fixed facts source; eligibility questions answered as asked; a three-verdict release call |

**Recommended start:** open [the lead contract](application-release-qa/SKILL.md), then follow one release through [the six-stage case](../../cases/one-opportunity-through-six-stages/04-marketing-operations.md).
