# Graders — the 7-check exit gate

> **Public edition.** Adapted from a production system. This file is exhibit **3b**: conversion QA before a candidate-market release. It asks whether the intended buyer sees relevant, defensible value quickly enough to take the next step. Design note: the grader **checks and points — it never restates rules and never re-edits**. Authority for each rule lives in the tailoring skill (`EXCERPT.md` beside this file shows its core) and the section-writing rules; a fail routes back to the owning definition, because a gate that invents standards at the door becomes a second, drifting rulebook.

## 1. Routing accuracy

Ask:

- In 6 seconds, who does the hiring manager read this candidate as? Is that the routing brief's correct pool?
- What is the strongest wrong pool, and does any part of the page push toward it?
- Can you state, in work-object language, the candidate's first operating move after joining — which object, action, beneficiary they'd stabilize first?

Fail signals: summary, experience labels, and skills don't read like one person applying for one kind of job; the wrong section leads the page; AI / tool / engineering / domain words steal the first identity; the pool is named but no first operating move can be said out loud.

## 2. Top 2–3 JD requirements

Ask:

- For the JD's 2–3 most important requirements, does the page carry *proof* — or only keywords?
- Was visibility improved through wording, labels, bullet emphasis, and summary connection — or by mutating the layout?
- Is any requirement written stronger than the body can defend?

Fail signals: the resume looks tailored only because JD words were added; or it looks polished but gives the hiring manager nothing to probe in an interview.

## 3. Translation and claim defensibility

Ask:

- Does every prominent work object, title, and label trace back through the translation test (true story → underlying capability → this JD's work object)?
- Does every claim respect the claim ceiling? Does any label or summary promise more than its bullet body?
- Is each line of target-role language *translating real work* — or *borrowing scope*? Can you name the work object, stakeholder, handoff, or output the hiring manager would buy it for?
- If AI / workflow is visible: did it pass the three-question test, at the tier the routing brief assigned?

Fail signals: regulated-domain jargon borrowing, title inflation, label–content mismatch, tool words patching a domain gap; the most JD-like sentence is also the least defensible one; "related" can be said but *how the capability enters this job's daily work* cannot; AI becomes the first identity — or its support-tier proof is buried where no reader can see the differentiated work quality.

## 4. Summary and page economy

Ask:

- Can the hiring manager read the summary and simultaneously see the proven pattern *and* how it serves this JD's work objects — in present-tense operating language, not desire?
- Is that reading backed by body proof, within the claim ceiling of adjacent / transferable cases?
- Does the first screen scan fast, or is it dragged by repetition and methodology filler?

Fail signals: the summary is the strongest part of the page and the body can't prove it; the summary exceeds the length discipline with no recorded exception; or it was "shortened" into abbreviations and coined nouns that read harder, not easier.

## 5. Source boundary and layout discipline

Ask:

- Did the tailoring start from the full skeleton of one designated baseline resume, preserving its visible identity system (layout, section order and presence, first-screen identity, entry naming, title phrasing)?
- Is every meaningful deviation *better than the source*, not merely *more like the JD*?
- If a title deviates from baseline, is the specific wrong-pool misread it prevents written down? ("Safer", "more neutral", "the source is stabler" are named-illegal justifications.)
- Were entries re-ordered against the baseline's real chronology? (Correct-pool reading must be carried by summary and bullet emphasis — never by rewriting history.)
- Did reference resumes contribute *angles* only, or did they smuggle in a second title system / section architecture / identity?

Fail signals: the tailor reads like a CV rebuild; identity drifted toward a reference; the final page is more generic than the baseline it started from.

## 6. Reframe-check discipline

Ask:

- Was the draft-reframe comparison run against *trusted, mature* references (recently completed, same or adjacent lane, production-final)? If skipped, is the concrete reason recorded?
- Was every adopted observation re-checked against this case's routing, truth sources, and claim boundary?

Fail signals: the comparison became a pre-writing source sweep — pretty sentences adopted before the HM read was stable; drafts, probes, or unfinalized artifacts treated as mature sources; a different lane's wording moved wholesale instead of its method.

## 7. Mode and write-back safety

Ask:

- Was this round production, proposal-only, or comparison — and did the write-back match the mode?
- Does the decision-trace file carry every required field (source decisions, Page Goal, capability matching, per-section trace, cold-read result or skip reason, grader result)?
- Did the tracker milestone land in the same turn?

Fail signals: a proposal contaminated the production resume or tracker; exported files treated as content truth; an external cold read treated as authority instead of blind-spot input; a large diff with no nameable improvement to the first read.

## Minimum bar

Any single fail blocks the ship:

- correct-pool routing
- top-requirement proof
- claim defensibility
- summary–body consistency
- source boundary / layout discipline
- reframe-check discipline
- write-back mode safety
