# 05 · Lifecycle Operations

**What this stage is for:** turning replies, silence, and timing into the right follow-up. After release, the market answers back — through the inbox, through relationship surfaces, through nothing at all — and this stage keeps that state as a ledger instead of a memory, so real people never wait on answers that were owed.

| | |
|---|---|
| **Inputs** | Inbound mail · own-account relationship surfaces · the relationship ledger and tracker state |
| **The decision** | *What changed, stalled, or needs action now?* |
| **Handoff** | Current relationship state plus the ranked next human action; outcomes and losses flow to [06 · Revenue Analytics](../06-revenue-analytics/README.md) |
| **Human authority** | Only verified closing states may auto-land; every positive signal and every outbound action waits for Johanna |

## Skills at this stage

| Skill | Role | The judgment it owns |
|---|---|---|
| **[Relationship Follow-Through](relationship-follow-through/SKILL.md)** | lead | What each real relationship deserves now — reply, open, wait, or close — and the one open loop a message should advance |
| [Inbox-to-Pipeline Sync](inbox-to-pipeline-sync/SKILL.md) | related | Inbox signals to governed lifecycle state — only high-confidence, uniquely matched closing states auto-land |
| [Relationship Ledger Sync](relationship-ledger-sync/SKILL.md) | related | Relationship state as a ledger, not a memory — with coverage gaps reported, never smoothed over |

**繁中摘要** — 這一站把回覆、沉默與時間變成正確的下一步。信箱訊號經語意判讀與確定性配對後分流：只有高信心、唯一匹配的關閉型狀態允許自動回寫，所有正面訊號（面試、回覆）一律停在 Johanna 面前；關係狀態靠證據帳本而非記憶維護，覆蓋不完整就照實回報。系統不代發任何訊息。
